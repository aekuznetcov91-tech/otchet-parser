## 1. НАЗНАЧЕНИЕ И БИЗНЕС-КОНТЕКСТ ПРОЕКТА

Проект **B2C Analytics Dashboard & Partners** — это корпоративная аналитическая платформа компании **СберАвто** (розничные продажи новых автомобилей, партнерская сеть официальных дилеров, сквозная воронка лидов и кредитная аналитика).

Платформа решает следующие задачи:
1. **Оперативный мониторинг продаж и выручки** (факт, темп run-rate, выполнение планов, ARPU, средний чек, маржинальность).
2. **Управление партнерской сетью (КАМ-модуль):** закрепление сотен дилерских холдингов за ключевыми менеджерами (КАМами), контроль активности дилерских центров («крыш»), постановка и контроль планов продаж дилеров.
3. **Сквозная 6-этапная воронка витрины и CRM (PostHog):** `Listing` ➔ `Card Show` ➔ `Card Click` ➔ `Offer` ➔ `Click Send` ➔ `Success` с разделением на ДЦ и ФДЦ.
4. **Контроль дебиторской задолженности (ДКП):** учет незакрытых предоплат, зависших авансов и формирование персональных реестров по должникам в Excel.
5. **Банковская аналитика:** сплит сделок по автокредитованию (Сбербанк, сторонние банки, собственные средства).

## 5. ПОШАГОВАЯ ИНСТРУКЦИЯ: КАК ОБНОВЛЯТЬ СДЕЛКИ (ETL И ДЕПЛОЙ)

Когда пользователь сгружает новый файл сделок (`DEAL_YYYYMMDD_...xls`) в папку `~/Downloads`:

### Шаг 1. Скопировать свежий файл в проект
```bash
cp /Users/vaceslavgamaunov/Downloads/DEAL_*.xls raw_data/
cp /Users/vaceslavgamaunov/Downloads/DEAL_*.xls .
```

### Шаг 2. Запустить ETL-парсер
```bash
python3 scripts/parser_engine.py
```
*Парсер автоматически обнаружит самый свежий файл, объединит его с кэшем истории, пересчитает выручку без НДС, проведет дедупликацию, сопоставит партнеров по Master ID и обновит `site/data.json`.*

### Шаг 3. Пересобрать витринную аналитику моделей
```bash
python3 scripts/build_showcase_q3_unified_excel.py
```

### Шаг 4. Запустить регрессионный пакет тестов
В проекте есть локальный Node.js для тестов в `scratch/tools/node-v20.18.0-darwin-arm64/bin`. Запускать строго так:
```bash
PATH="/Users/vaceslavgamaunov/Desktop/Dashboard_usualy/otchet-parser/scratch/tools/node-v20.18.0-darwin-arm64/bin:$PATH" python3 -m unittest discover tests
```
*Все 82 теста обязаны завершиться со статусом `OK`.*

### Шаг 5. Задеплоить на Cloudflare Pages и синхронизировать Git

*Скрипт синхронизирует фронтенд, проверит размеры и тесты, закоммитит и отправит изменения в `origin/main`, затем опубликует в Cloudflare архив из проверенного SHA.*

## 6. КЛЮЧЕВЫЕ БИЗНЕС-ПРАВИЛА И НЕПРЕЛОЖНЫЕ ИНВАРИАНТЫ

1. **🚨 Синхронизация Git ⟷ Cloudflare Pages:**
   * Любые изменения, попадающие на Cloudflare Pages, **ОБЯЗАНЫ** быть закоммичены и отправлены в Git `origin main`. Никаких рассинхронизаций.
2. **🛡️ Сохранение историчности (Historical Preservation):**
   * Закрытые месяцы с начала года (`2026-01` ... `2026-08`) **НЕИЗМЕННЫ**. Например, август строго равен **1 776 сделкам** в `sys_db`. Свежие файлы актуализируют только сентябрь и октябрь.
3. **🏢 Определение «Крыши» (Rooftop):**
   * **1 Крыша** = уникальная связка **`(Партнер + Город + Бренд)`**.
   * Если у АвтоГермеса в Москве 8 брендов — это 8 крыш.
   * **Активная крыша:** $\ge 1$ закрытая сделка за выбранный месяц.
4. **📅 Правило выбора месяца по умолчанию (Default Month):**
   * Если пользователь открывает дашборд **с 1 по 3 число** месяца $X$, по умолчанию автоматически открывается месяц $X-1$ (прошлый месяц), чтобы сразу видеть полные итоги закрытого месяца. С 4-го числа открывается текущий месяц $X$.
5. **🚫 Строгий запрет на задвоение лидов (No Double Counting):**
   * Переданные дилеру лиды берутся **только** из `sys_db_partners` (`Type === 'Лид'`). Категорически запрещено суммировать их с `lead_geo_dealers`.
6. **💰 Финансовая формула:**
   * Комиссия СберАвто = 2% от суммы ДКП.
   * Выручка без НДС = `Комиссия / 1.22`.
   * Канал **Опт МП2 (Wholesale, холд 1 000 ₽) СТРОГО ИСКЛЮЧЕН** из розничной воронки конверсий витрины.
7. **🧱 Модульность JavaScript:**
   * Запрещено возвращать код в монолит `site/index.html`. Вся логика строго распределена по модулям в `site/js/*.js`.
8. **📦 Ограничение размера файлов Cloudflare:**
   * Cloudflare Pages не принимает файлы больше 25 MiB. `site/data.json` сейчас весит ~16.65 MiB. `deploy_to_cloudflare.py` проверяет размер каждого публикуемого файла и останавливает выпуск при превышении лимита; JSON формируется компактным на этапе ETL.
