## 3. ИНСТРУКЦИЯ ДЛЯ РАЗРАБОТЧИКА (БЫСТРЫЙ СТАРТ)

### 1. Получение последних изменений из Git:
```bash
git checkout main
git pull origin main
```

### 2. Запуск локального дашборда для тестирования:
```bash
python3 -m http.server 8080 -d site
```
После запуска открыть в браузере: `http://localhost:8080/index.html`.

### 3. Обновление данных (ETL):
При поступлении свежих выгрузок сделок (`DEAL_YYYYMMDD_...`) или лидов (`data (X)...`):
1. Поместить файлы в корневую директорию проекта и `raw_data/`:
   ```bash
   cp ~/Downloads/DEAL_*.xls raw_data/
   cp ~/Downloads/DEAL_*.xls .
   ```
2. Запустить ETL-парсер:
   ```bash
   python3 scripts/parser_engine.py
   ```
3. Скрипт автоматически найдет свежие файлы, проведет дедупликацию, пересчитает выручку без НДС, сопоставит партнеров по Master ID и обновит `site/data.json`.
4. Пересобрать витринную Excel-таблицу:
   ```bash
   python3 scripts/build_showcase_q3_unified_excel.py
   ```

### 4. Запуск автоматических тестов:
Перед любым коммитом или деплоем обязательно прогнать тесты (с локальным Node в PATH):
```bash
PATH="/Users/vaceslavgamaunov/Desktop/Dashboard_usualy/otchet-parser/scratch/tools/node-v20.18.0-darwin-arm64/bin:$PATH" python3 -m unittest discover tests
```
Все **52 теста** должны завершаться со статусом `OK`.

### 5. Деплой на Cloudflare Pages:
Для отправки изменений на боевой сервер выполните:
```bash
python3 deploy_to_cloudflare.py
```
Скрипт выполнит сборку, валидацию файлов, деплой на Cloudflare Pages и автоматический `git push` в репозиторий GitHub.

## 4. ПРАВИЛА РАБОТЫ И ИНВАРИАНТЫ КОДОВОЙ БАЗЫ

1. **🚨 Синхронизация Git и Cloudflare:**
   - Всё, что деплоится на Cloudflare Pages, **ОБЯЗАТЕЛЬНО** коммитится и пушится в Git (`origin main`). Никаких рассинхронов между локальной разработкой и репозиторием.
2. **Модульность JavaScript:**
   - Запрещено переносить логику обратно в `site/index.html`. Все доработки вносятся строго в модули `site/js/*.js` (`charts.js`, `tables.js`, `debtors.js`, `funnel.js`, `lead-geo.js`, `kam-dashboard.js`, `utils.js`).
3. **Master Partner Registry:**
   - Редактирование привязок дилеров осуществляется через `data/partners_registry.json`. При изменениях обязательно запускать `python3 scripts/parser_engine.py` для обновления боевых файлов.
4. **Формат ссылок BFS:**
   - Прямой адрес на карточку клиента в CRM Backoffice строго формируется по шаблону:
     `https://backoffice.x.sberauto.com/crm/manager/{client_id}`
5. **Финансовая модель:**
   - Комиссия СберАвто = 2% от суммы ДКП.
   - Выручка без НДС = `Комиссия / 1.22`.
   - Опт МП2 (Wholesale, холд 1 000 ₽) **СТРОГО ИСКЛЮЧЕН** из розничной воронки конверсий.
6. **Определение «Крыши» (Rooftop):**
   - 1 «крыша» = 1 бренд в 1 городе конкретного дилера.
   - Активная крыша = $\ge 1$ закрытая сделка за месяц.
