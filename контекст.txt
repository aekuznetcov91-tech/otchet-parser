# ТЕХНИЧЕСКИЙ КОНТЕКСТ ПРОЕКТА: DASHBOARD PARTNERS

## 1. АРХИТЕКТУРА И РАЗДЕЛЕНИЕ КОМПОНЕНТОВ
Проект состоит из двух полностью независимых частей:
А) Парсер (Frontend-only утилита для обработки Excel, используется локально).
Б) Дашборд (Frontend SPA для визуализации, развертывается на хостинге/Cloudflare).
Связующее звено: файл `data.json`, который генерируется Парсером и читается Дашбордом.

## 2. ПАРСЕР (`parser.html`)
- **Среда выполнения:** Локальный браузер на рабочем ПК пользователя (ограниченная среда без Node.js и бэкенда).
- **Зависимости:** SheetJS (`xlsx.full.min.js` загружается через CDN/локально).
- **Логика работы:**
  1. Пользователь загружает 2 файла Excel: "Сделки" и "Авансы".
  2. Парсер объединяет строки по ключу "VIN" (уникальный идентификатор).
  3. Происходит нормализация данных (очистка сумм от НДС (деление на 1.2), стандартизация названий брендов (CHERY, LADA и др.), расчет полей SaleQty, PrepayQty, Revenue, Price).
  4. Формируется два массива: `sys_db` (основная база) и `sys_db_partners` (лиды партнеров).
  5. Сохранение: По клику на "Сгенерировать и сохранить JSON" используется `window.showSaveFilePicker` (File System Access API). Пользователь вручную выбирает папку `site` для сохранения `data.json`. Реализован фолбэк на стандартное скачивание (blob/anchor), если API не поддерживается.
- **Деплой/Сервер:** Отсутствует. Все API-вызовы и автоматические деплои через Python/Wrangler были вырезаны для работы в строго изолированной рабочей среде.

## 3. ДАШБОРД (`site/index.html`)
- **Среда выполнения:** Веб-браузер. Размещается статикой на Cloudflare Pages (`dashbord-partners1.pages.dev`), проксируется через Cloudflare Workers (`dashbord-partners.beckelaguas723.workers.dev`).
- **Внешние библиотеки:** Tailwind CSS (через CDN), Chart.js + chartjs-plugin-datalabels, Lucide Icons, html2canvas (для копирования DOM в буфер).
- **Логика загрузки данных:** В `window.onload` вызывается `loadData()`, которая через `fetch('data.json?v=timestamp')` получает собранный парсером JSON. Кэширование сбрасывается параметром `?v=`. При ошибке выводится `alert`.
- **Структура UI (Табы):**
  1. Дашборд (Диаграммы) — KPI, круговые диаграммы сплита брендов, линейные графики динамики.
  2. Динамика по месяцам (Сводная таблица).
  3. Свод партнеров.
  4. Свод менеджеров.
  5. Ожидание (таблица).
- **Особенности функционала:**
  - **Копирование графиков:** `html2canvas` с прозрачным фоном (`backgroundColor: null`). Копируется строго контейнер (canvas + HTML-легенда, выстроенные через flex-row).
  - **Копирование таблиц:** JS генерирует TSV и пишет напрямую в `navigator.clipboard.writeText(tsv)`.
  - **Умный поиск:** Функция `setupSmartSearch` собирает уникальные значения и создает `<datalist>` для автокомплита.

## 4. ПРОЦЕСС РАБОТЫ (WORKFLOW) ПОЛЬЗОВАТЕЛЯ
1. Открывает локальный `parser.html`.
2. Загружает 2 Excel-отчета (Сделки и Авансы).
3. Генерирует JSON, выбирает локальную директорию `/site` и перезаписывает `data.json`.
4. В терминале деплоит папку `site` на Cloudflare (`npx wrangler pages deploy site`).
5. На дашборде нажимает "Обновить" для загрузки нового `data.json`.

## 5. ВАЖНЫЕ НЮАНСЫ И ОГРАНИЧЕНИЯ ДЛЯ ИИ
- **НИКАКОГО Node.js в парсере:** Установка npm-пакетов невозможна.
- **Верстка:** Только классы Tailwind. Никаких самописных CSS без крайней необходимости.
- **Экспорт графиков:** `html2canvas` плохо справляется с `truncate` и flex-переносами. Легенды реализованы через `break-words` и жесткое позиционирование flex-row для идеальных скриншотов.
- **Математика KPI:** Выручка Тотал = Выручка Китай + Выручка LADA. Разделение жестко зашито в функцию `updateAllTabs()`. 
- **Синхронизация ID:** При редактировании HTML-структуры KPI необходимо синхронно обновлять вызовы `document.getElementById` в JS, иначе графики не рендерятся.
