## 📌 РЕЗЮМЕ ДЛЯ КОМАНДЫ (TL;DR)

В ходе технического аудита кодовой базы и расчётов сформирован пакет архитектурных улучшений и подготовлено **20 новых автоматических тестов** (общее тестовое покрытие проекта расширено **с 21 до 41 теста**).

Ключевые решения закрывают 4 системные задачи:
1. **Исключение перетирания прошлых месяцев при смене КАМа** (введена датированная история закреплений `effectiveMonth`).
2. **Строгая математическая модель «Крыш»** на базе SHA-256 хеша четвёрки `(Партнёр + Бренд + Город + Адрес)`.
3. **Ускорение первого экрана в 3–5 раз** за счёт разделения монолитного 12.3 МБ `data.json` на лёгкий `overview.json` и ленивую подгрузку вкладок.
4. **Безопасность данных и онлайн-сохранение справочника** через Cloudflare Pages Functions напрямую в Git.

## 1. АРХИТЕКТУРА ДАННЫХ И БИЗНЕС-ЛОГИКА

### А) Историчность закреплений КАМов (`kam_effective_from`)
* **Проблема:** Ранее при смене ответственного КАМа за дилером в сентябре (например, передача портфеля новому менеджеру) повторный пересчёт пайплайна за август мог задним числом перезаписать сделки на нового сотрудника, искажая закрытый факт месяца.
* **Решение (`scripts/audit_metrics.py`):**
  * В структуру партнёра вводится массив `kam_assignments` с атрибутом `month: "YYYY-MM"`.
  * Функция `apply_manual_assignments(partners, rows, current_month)` применяет закрепление только к тем периодам, которые равны или позже даты вступления в силу.
  * **Результат:** Факт августа (1 778 сделок: Кузнецов 690, Чихарев 578, Дариенко 328, Солдатова 181) зафиксирован навсегда и математически изолирован от любых сентябрьских правок.

### Б) Строгая формула «Крыш» (Дилерских центров)
* **Стандарт:** $1\text{ Крыша} = \text{SHA256}(\text{PartnerId} + \text{Dealer} + \text{Brand} + \text{Address})$.
* **Правила резолвинга (`resolve_rooftop`):**
  * Дилерские центры одного партнёра с одинаковым брендом в одном городе, но расположенные по **разным фактическим адресам**, больше не схлопываются в одну точку.
  * Если в сделке адрес не указан или допускает неоднозначное толкование среди нескольких ДЦ дилера — сделке присваивается статус `RooftopMatch: 'ambiguous'`, и она **не увеличивает счётчик активных крыш ошибочно**.
  * Неизвестные/неопознанные локации остаются в статусе `unmatched`.

### В) Идемпотентная дедупликация реестра (`unique_partners`)
* Алгоритм консолидации устраняет дублирование Master ID в `partners_registry.json`, объединяя при этом все исторические псевдонимы (`bitrix_aliases`, `bi_aliases`, `pochta_aliases`) и вложенные адреса автосалонов без потерь данных.

### Г) Честная воронка без синтетических допущений
* На витрине воронки PostHog и в CRM-этапах отображаются исключительно фактически зарегистрированные события.
* Если событие отсутствует в выгрузке — выводится честный статус `«Нет данных»`, синтетические коэффициенты-заглушки исключены.
* Канал розницы строго изолирован от оптовых программ МП1, МП2 и МП3.

## 2. ПРОИЗВОДИТЕЛЬНОСТЬ: РАЗДЕЛЕНИЕ ДАТАСЕТА (LAZY LOADING)

* **Текущее состояние:** При каждом визите пользователя браузер скачивает единый файл `data.json` размером **12.3 МБ**, что замедляет запуск дашборда на мобильных устройствах и слабом канале.
* **Целевая схема (Split Payload):**
  1. **`site/overview.json` (~1.5–2 МБ):** Базовые метрики, динамика продаж, сплит брендов, операционные таблицы первого экрана. Загружается мгновенно (< 300 мс).
  2. **`site/lead-clients.json` (~6–7 МБ):** Детальная база 236K+ лидов со ссылками на BFS Backoffice. Подгружается асинхронно только при клике на вкладку *«Лиды / География»*.
  3. **`site/banking.json` (~1.5 МБ):** Реестр кредитных договоров и банковской аналитики. Подгружается только при переходе на вкладку *«Банки»*.
  4. **`site/data.json`:** Сохраняется в корне для полной обратной совместимости со старыми скриптами.

## 3. БЕЗОПАСНОСТЬ И ДОСТАВКА (CLOUDFLARE PAGES FUNCTIONS)

### А) Сквозная защита периметра (`functions/_middleware.js`)
* Реализован middleware на базе Cloudflare Pages Functions, проверяющий HTTP Basic Auth с защитой от тайминг-атак (криптографическое сравнение SHA-256 хешей через `crypto.subtle`).
* В отличие от внешнего прокси, middleware защищает **весь периметр** `pages.dev`, включая прямые ссылки на JSON-файлы, отчёты и внутренние скрипты.
* При отсутствии настроенных переменных окружения возвращает безопасный статус `503 Service Unavailable`, предотвращая утечку данных при сбоях конфигурации.

### Б) Серверный API сохранения справочника (`functions/api/save-partners.js`)
* Позволяет на странице сопоставления (`partner_matcher.html`) корректировать привязки дилеров и сохранять их по кнопке в UI.
* Запрос проверяет уникальность ID, фиксирует месяц действия (`effectiveMonth`), проверяет SHA коммита (защита от перезаписи чужих правок) и через GitHub API создаёт чистый коммит сразу во все 3 копии реестра (`site/`, `data/`, корень).
