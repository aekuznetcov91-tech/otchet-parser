1. АРХИТЕКТУРА СИСТЕМЫ И ИСТОЧНИКИ ДАННЫХ
--------------------------------------------------------------------------------
Система объединяет 4 ключевых слоя:

А) Единая папка сырых данных (`raw_data/`):
- Содержит входящие файлы сделок, лидов, справочников и скриншотов витрины.
- Файлы могут иметь произвольные имена: движок автоматически определяет назначение по набору столбцов.
- Интегрированы скриншоты витрины PostHog (`Jetour/статистика витрина`) и оцифрованы через Apple Vision OCR.

Б) Автономный серверный и локальный парсер (`scripts/parser_engine.py`):
- Потоковое чтение XML для сверхбыстрой обработки файлов любого объема (включая лиды на 150 000+ строк и сделки на 20 000+ строк).
- Умный поиск шапок таблиц со смещением.
- Автоматическая очистка выручки от НДС (`comm / 1.22`).
- Отсечение дублирующих фин. продуктов (Кредит Сбер, ФинКАСКО, КАСКО Плюс).
- Подсчет физических выданных автомобилей.
- Динамический многомесячный расчет сквозной воронки 13 брендов (`JETOUR`, `LADA`, `TENET`, `CHANGAN`, `GAC`, `SOLARIS`, `SOUEAST`, `BELGEE`, `GEELY`, `HAVAL`, `JAECOO`, `OMODA`, `МОСКВИЧ`) за `2026-08`, `2026-07` и `all`.
- Формирование `site/data.json`.

В) Интерактивный SPA-дашборд (`site/index.html`):

- Табы:

--------------------------------------------------------------------------------
2. СТРУКТУРА JSON (`data.json`)
--------------------------------------------------------------------------------
Объект содержит:
- `sys_db`: массив всех сделок, авансов и ожиданий.
- `sys_db_partners`: массив операций в партнерском разрезе (с привязкой КАМ).
- `funnel_metrics`: кликстрим витрины PostHog.
- `brand_funnel`: структура сквозной воронки с поддержкой `months` и `by_month` (`2026-08`, `2026-07`, `all`) по 13 брендам.

--------------------------------------------------------------------------------
3. МАТЕМАТИКА, БИЗНЕС-ПРАВИЛА И СЦЕНАРНОЕ МОДЕЛИРОВАНИЕ
--------------------------------------------------------------------------------
1. Количество сделок = sum(SaleQty) по записям с SaleQty == 1 (реальные автомобили, без доп. продуктов).
2. Количество авансов = sum(PrepayQty) по записям с PrepayQty == 1.
3. Тотал Выручка = sum(Revenue) по всем закрытым сделкам (SaleQty == 1, сумма комиссии / 1.22).
4. **Бизнес-правило:** Сделки МП2 категорически не могут быть сделками по передаче лида (МП2 — оптовый маркетплейс, Передача лида — розничный канал).
5. Воронка брендов:
   - Расчет конверсий ведется без учета МП2.
   - Квалификация: целевые лиды (`Целевой == 1`).
   - Развилка: Ветка ДЦ (передача лида) vs Ветка ФДЦ (онлайн-заявки и одобрения).
6. **Сценарное моделирование на 1 650 авто vs Бюджетный план (59.17 млн ₽ / 1 592 авто):**
   - Сценарий 1 (База, 1650 авто): Выручка 61.14M ₽ (+3.3% к плану).
   - Сценарий 2 (Все МП2=20k кроме LADA): Выручка 38.81M ₽ (-34.4% к плану).
   - Сценарий 3 (МП2=20k только JETOUR): Выручка 48.04M ₽ (-18.8% к плану).
   - Сценарий 4 (Потеря 50% сделок МП2): Выручка 38.18M ₽ (-35.5% к плану, 1 036 авто).
