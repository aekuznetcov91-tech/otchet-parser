# Feature Specification: Fix KAM Partner Hierarchy Subrows and "Авто Премиум Тверь" Allocation

## 1. Background & Problem Statement
Users of the B2C Analytics Dashboard & KAM matrix reported two critical issues:
1. **"Авто Премиум Тверь" appears under Светлана Дариенко:**
   - In accordance with the KAM assignment matrix, "Авто Премиум Тверь" (ID 1040, ООО "СОЮЗ-Т") must be assigned strictly to **Алексей Чихарев**, while "Премиум Авто ONLINE" (ID 632032, СПб) belongs to **Светлана Дариенко**.
   - However, in the KAM dashboard table (`Реестр партнеров КАМ: Города и Бренды`), when filtering by Светлана Дариенко, a row for ID 1040 "Авто Премиум Тверь" appeared with 0 deals.
   - Root cause: In `partners_registry.json`, ID 1040 had `holding: "ONLIN"`. Because substring matching in `matchDealerToPartner` checked `dn.includes(a)` for aliases with length >= 4, any dealer containing the word "online" (e.g. `Online ООО "АВТОЛИГА"`, which belongs to Дариенко) was erroneously matched to partner ID 1040, creating a dummy duplicate row under Дариенко.
2. **Dealer rows do not expand to show brands:**
   - When clicking on dealer rows (such as ID 1040 and ~71 other partner rows in the KAM dashboard), the disclosure triangle arrow toggles to point down (`▼`), but no subrows appear.
   - Root cause: In `renderKamTable()`, subrows are generated by looping strictly over `p.cities`. If a partner has no OEM data or empty `p.cities`, but has brands in `p.brands`, `Object.entries(p.cities || {})` iterates 0 times, creating 0 `<tr class="kam-subrow-...">` elements. The toggle function rotates the arrow, but finds no DOM elements to reveal.

## 2. User Stories & Acceptance Criteria

### User Story 1: Accurate KAM Allocation for Авто Премиум Тверь
- **As a** Sales Director / KAM Manager,
- **I want** "Авто Премиум Тверь" (ID 1040) to be assigned exclusively to Алексей Чихарев,
- **So that** it never appears under other KAM managers (like Светлана Дариенко) and other "Online ..." dealers are not incorrectly hijacked by ID 1040.

**Acceptance Criteria:**
- [x] In `partners_registry.json`, `data.json`, and `site/data.json`, ID 1040 has `canonical_name: "Авто Премиум Тверь"`, `holding: "Авто Премиум"`, `kam: "Алексей Чихарев"`, and no generic `ONLIN`/`ONLINE` alias.
- [x] `matchDealerToPartner()` filters out generic stop-words (`online`, `ооо`, `авто`, etc.) from substring matching aliases, preventing false matches.
- [x] When filtering KAM = "Светлана Дариенко", ID 1040 does NOT appear.
- [x] When filtering KAM = "Алексей Чихарев" or "Все КАМы", ID 1040 appears exclusively under Алексей Чихарев.

---

### User Story 2: 100% Reliable Brand Subrow Expansion
- **As an** Analyst / User,
- **I want** every dealer with brands/deals to reliably expand and display its cities and brands when clicked,
- **So that** I can inspect the brand split for all partner centers without encountering empty or non-functional accordions.

**Acceptance Criteria:**
- [x] In `getKamAggregatedData()`, when a partner has brands or transactions but `p.cities` is empty (no OEM geo), the partner automatically falls back to registering the brand under its deal city or `"Город не указан"`.
- [x] In `renderKamTable()`, if `p.cities` is empty but `p.brands` has entries, subrows are rendered under a fallback city (`Город не указан`) containing all of the partner's brands.
- [x] All 71 previously broken partners now render valid `<tr class="kam-subrow-...">` rows and expand smoothly on click.
- [x] The `safeKey` generator produces collision-free and valid DOM class identifiers for all Cyrillic and special-character partner names.
