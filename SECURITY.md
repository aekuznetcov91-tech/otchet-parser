# Защита дашборда

Обновлено 04.10.2026. Изменения не пересчитывают сделки, выручку или закрытые месяцы.

## Работающий контур

- `workers/dashboard.mjs` — сервер API и прокси. `site/_worker.js` генерируется из
  `workers/security.mjs` и `workers/pages-entry.mjs`; защищает **все** маршруты Pages,
  включая JSON, HTML и вложения. `_routes.json` не исключает статические файлы.
- Basic-доступ позволяет просмотр. Новый случайный пароль хранится только в
  `config.local.json`, его SHA-256 — в секрете `AUTH_DIGEST` Cloudflare.
  Старый общий пароль сменён. Не возвращать секреты в документацию или код.
- Персональные случайные пароли КАМов проверяет сервер по `KAM_PASSWORD_HASHES`.
  Пароли генерируются из 24 случайных байт; простые пользовательские пароли вместо
  них использовать нельзя. Для пользовательских паролей нужен password KDF или SSO.
- Сессия — случайный 256-битный токен, HttpOnly/Secure/SameSite=Strict cookie;
  на сервере хранится только хэш токена. Срок 8 часов, выход отзывает сессию.
  Вход ограничен 10 попытками за 15 минут для пары источник/учётная запись.
- Запись требует сессии, разрешённого Origin, специального заголовка, JSON,
  целочисленных планов 0–100000 и серверного права на каждый ключ.
  Права строятся из актуального портфеля и доверенного реестра. Неизвестные и
  неоднозначные ключи доступны только руководителю. Суффикс КАМа из запроса
  сам по себе не даёт прав.
- `PlanStore` (Durable Object) атомарно сравнивает номер версии и сохраняет изменения.
  Одновременное сохранение устаревшей версии получает 409, а не затирает чужие правки.
  До изменения сохраняется снимок и журнал с автором/временем/значениями до и после.
  Старое KV-хранилище импортируется один раз и остаётся резервной копией.
- Ответы имеют no-store, nosniff, DENY/frame-ancestors, no-referrer; wildcard CORS удалён.
  Ограничения CSP на фреймы/объекты/base/form включены. Строгий script-src пока
  **Report-Only**: для его включения потребуется убрать оставшиеся inline-обработчики
  в старом интерфейсе. Это не полное устранение всех возможных XSS.
- Исправлены подтверждённый XSS менеджеров, значения карточек лидов, ряд шаблонов
  справочника и аргументы полей планов. CRM-ссылки разрешены только на HTTPS-хост
  `backoffice.x.sberauto.com`. SheetJS — 0.20.3, скрипты размещаются локально;
  контрольные суммы и исходники загрузки — `site/vendor/manifest.json`.

## Выпуск и проверка

1. `python3 scripts/sync_frontend.py`
2. `node scripts/build_security.cjs`
3. `python3 -m unittest discover tests` (Node обязателен для security-тестов).
4. `python3 scripts/scan_secrets.py`; `git diff --check`.
5. Внести изменения через PR и проверить CI. При доступной защите main включить
   обязательный `security-and-tests`, review, запрет force push/удаления и обхода админом.
6. После слияния обновить локальный main и выполнить
   `python3 deploy_to_cloudflare.py --existing-main`.
   Деплой использует только чистый SHA, совпадающий с origin/main; сначала Worker,
   затем Pages. Bootstrap без защиты ветки допускает обычный режим публикации.
7. В обоих окружениях Pages обязательно `fail_open=false`. Старые публикации без
   защиты необходимо снять с хостинга, иначе их адреса обходят новый обработчик.
8. Без входа проверить оба домена и адрес нового деплоя: HTML/JSON/API должны отдавать
   401/403, а не данные. С правильным входом — 200. Не делать боевые тестовые записи.

Локальный сканер выпуска проверяет текущие файлы и добавления в новых коммитах на типовые токены и закрытые
ключи. Это ограниченный сканер, а не замена полноценному Gitleaks/Secret Protection.
Историческая находка из аудита не считается отозванной без подтверждения владельца.

## Восстановление планов

Руководитель может прочитать `GET /api/kam-plans/audit` и восстановить снимок через
`POST /api/kam-plans/restore` с JSON `{"revision": <текущая>, "snapshot": <нужная>}`.
Запрос выполняется из авторизованной страницы с `X-Dashboard-Request: 1` и JSON
Content-Type. Восстановление создаёт новую версию и сохраняет предыдущую; не удаляет
историю. Проверено автоматическим тестом на изолированном хранилище.

## Внешние шаги, требующие владельца аккаунтов

- Cloudflare Access/SSO/MFA: текущий токен получает 403 от Access API. Нужен доступ
  владельца и список корпоративных адресов. Серверные пароли — промежуточная мера.
- Отзыв исторического Cloudflare-токена: текущий токен получает 403 при управлении
  API-токенами. Проверить и отозвать старый токен через профиль владельца. Не выводить
  его значение и не переписывать Git history до отзыва и согласованной миграции клонов.
- Google: `security/google-analytics.gs` — подготовленная серверная версия. Она
  запрещает GET, разрешает экспорт только POST с серверным `ANALYTICS_READ_TOKEN`,
  запись — с отдельным `ANALYTICS_WRITE_TOKEN`. Секреты задаются в Script Properties.
  Перед публикацией перевести отправку событий калькулятора на доверенный сервер:
  **запрещено вставлять сервисный токен в браузерный JavaScript**. После публикации
  закрыть старые версии Apps Script и проверить отсутствие анонимного чтения.
  Для обновления дашборда задать `calculator_analytics_read_token` в локальном конфиге.
  До настройки безопасного экспорта текущий агрегат сохраняется, обновление возможно
  через `scripts/sync_calculator_analytics.py --input <локальный JSON>`.
- Проверить владельцев двух старых write deploy keys. Не удалять чужой рабочий доступ
  без замены. Локальный origin больше не содержит токен: используется ограниченный
  этим репозиторием HTTPS helper и неотслеживаемый config с правами 0600.
  Проверка SSH (включая отдельный новый deploy key) завершилась ошибкой чтения
  репозитория; созданный для проверки ключ отозван. Старые ключи не менялись.

- GitHub Secret Protection может быть недоступен по тарифу. Репозиторий должен
  оставаться Private; не делать его публичным ради включения бесплатной защиты ветки.

Доступность анонимного чтения ранее подтверждена. Прошлый факт злонамеренного доступа
не установлен; для его расследования нужны журналы владельцев Cloudflare/Google/GitHub.

## Активация GitHub Actions

Готовый workflow: `security/github-actions-workflow.yml`. Публикация в
`.github/workflows/` отклонена GitHub: у PAT нет scope `workflow`. После исправления
доступа владельцем перенести файл в `.github/workflows/security.yml` и проверить
успешный запуск. До этого CI не включён; выпуск запускает тесты и сканер локально
и останавливается при ошибке.
